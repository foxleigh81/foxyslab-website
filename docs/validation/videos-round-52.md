## Verification changes

The existing production browser suite now invokes a bounded interaction checker
on desktop and mobile. It checks a populated title search, no-match search and
clearing, playlist selection with the advertised count and heading, forward
pagination with changed cards, back pagination restoring cards, and a fresh
direct playlist navigation reproducing the selected cards. Both pagination
directions are explicitly not applicable only when the displayed dataset count
is between one and twelve. A missing control for a larger dataset is a failure.

The first visible card image's actual DOM `fetchpriority` attribute is observed
before interaction. The result is `high`, `low`, `auto`, `absent`, or `invalid`;
source props and preload links are not substituted for that observation. An
observed hint is not labeled a passing performance assertion.

Empty/error fixtures are generated by the existing real VideosPage server-render
tests using mocked YouTube results. Browser checks intercept only their own
page navigation and inspect that actual markup. They check the rendered state,
visible empty/error copy, and absence of cards. These outcomes are labeled
`fixture`; they verify server markup without hydration, not live API failure
handling. Existing component tests cover client interactions separately. The
synthetic interaction-verifier tests also are not live application evidence.

Only allowlisted project, source, check, outcome, and priority enums enter
`summary.json`. Titles, slugs, URLs, raw responses, assertion messages, and
attachments from browser results are discarded. Synthetic credential tests
cover retained summaries and console output on success and failure, including
malicious fields and an injected priority value. No common-pattern scan is
used as the proof. Raw browser/Lighthouse output and generated fixture markup
are deleted; the workflow continues uploading only `summary.json`.

Browser results are written before Lighthouse begins and survive measurement
failure. The existing server-card/footer-through-hydration regression and three
mobile CLS/LCP measurements remain in place. No page behavior, workflow YAML,
deployment, or credential configuration was changed.
